# Backend — Лабораторная работа 1 (DevOps)

REST-бэкенд на Flask. Принимает текстовые данные с фронтенда и сохраняет их
в файл `data.txt` на сервере.

## Версии

| Тэг   | Содержимое                                              |
|-------|---------------------------------------------------------|
| v1.0  | `POST /api/data` — прием данных и запись в `data.txt`    |
| v2.0  | дополнительно `GET /api/data` — чтение содержимого `data.txt` (с необязательным поиском) |

## Установка и запуск

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Сервис запускается по адресу <http://127.0.0.1:5001>.

## Эндпоинты

### `GET /api/health`

Служебный эндпоинт для проверки доступности сервиса.

Ответ:

```json
{ "status": "ok", "version": "1.0" }
```

### `POST /api/data` (v1.0)

Принимает JSON с полем `text` и дописывает его в конец `data.txt`.

Запрос:

```json
{ "text": "Привет, сервер!" }
```

Успешный ответ (`201`):

```json
{ "status": "ok", "message": "Данные сохранены в data.txt", "records": 1 }
```

Если поле `text` пустое, возвращается `400`:

```json
{ "status": "error", "message": "Поле 'text' не должно быть пустым" }
```

### `GET /api/data` (v2.0)

Возвращает содержимое файла `data.txt`. Если файл еще не создан, `content`
будет пустой строкой, а `count` — `0`.

Ответ:

```json
{
  "status": "ok",
  "message": "Содержимое файла data.txt",
  "count": 2,
  "total": 2,
  "content": "Привет, сервер!\nВторая запись"
}
```

Дополнительно поддерживается необязательный параметр `query` — поиск
подстроки по данным без учета регистра: `GET /api/data?query=запись`.
В таком случае в `content` попадут только подходящие строки, а `count`
покажет количество найденных записей. Если `query` не передан, возвращается
все содержимое файла.

## Проверка вручную

```bash
curl -X POST http://127.0.0.1:5001/api/data -H "Content-Type: application/json" -d "{\"text\": \"Привет\"}"
curl http://127.0.0.1:5001/api/data
```

## Запуск в Docker

Сборка образа версии 2.0:

```bash
docker build -t backend:2.0 .
```

Запуск контейнера (данные сохраняются в томе `backend-data`):

```bash
docker run -d --name backend -p 5001:5001 \
  -e HOST=0.0.0.0 -e DATA_FILE=/data/data.txt \
  -v backend-data:/data backend:2.0
```

В рамках лабораторной работы сервис запускается через `docker compose`
из репозитория DevOps, где он объединен в сеть с фронтендом.

### Переменные окружения

| Переменная  | По умолчанию            | Назначение                                   |
|-------------|-------------------------|----------------------------------------------|
| `DATA_FILE` | `data.txt` рядом с app  | путь к файлу данных (в Docker — точка тома)  |
| `HOST`      | `127.0.0.1`             | адрес прослушивания (в Docker — `0.0.0.0`)   |
| `PORT`      | `5001`                  | порт сервиса                                 |

## Структура проекта

```
backend/

```
